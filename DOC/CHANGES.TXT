-------------------------------------------------------------
SXED Screen X Text Editor - version history
2024 - 2026 Armando Pérez Abad

Newest first. The manual is SXED.TXT.
-------------------------------------------------------------


 -------- v0.8 (2026-10-16)

Improved
- S2ED edits much faster on the MSX1: Enter ~200 -> ~120
  ms, a BS / DEL join ~380 -> ~130 ms, a one-row scroll
  ~210 -> ~115 ms, a page of long lines ~600 -> ~310 ms.
  Only the rows whose colours changed are sent to the
  screen, rows are composed twice as fast, a join moves the
  rows below instead of redrawing the page, and new rows
  are composed before the screen is updated, so no line is
  seen twice for a moment.
- All editors: a line without * or _ skips the markup scan.
- Line records hold text only (styles come from the markup
  when a line is painted): twice the lines per mapper
  segment (S6ED 202, S2ED / S61ED 264) and twice the undo
  steps (about 45 on S6ED, 56 on S2ED / S61ED).
- Memory headroom increased substantially across all targets:
  S2ED reaches 1,280 B free in TPA (+512 B) and 564 B in
  FTRSEG (+113 B); S6ED / S61ED reach over 2,400 B free in
  TPA (+451 B) and over 2,640 B in FTRSEG (+322 B).
  Vestigial attribute clears and 512-byte buffer copies are
  pruned from edits, joins and undo, undo pack/unpack is
  unified, and CFG and menu shortcut dispatches use compact
  lookup tables.
- File browser: TAB key switches focus instantly (~4 ms vs
  ~40 ms) by updating only the active row (S2ED) or the
  buttons and slider (S6ED / S61ED) instead of blitting the
  entire grid or dialog.
- S2ED scroll: empty rows past the end of the file skip
  VRAM colour table dumps when their colours match the
  editor background.
- S2ED: dialogs and menus open with a single screen
  update instead of two.

Changed
- TXT mode: BS at column 0 or DEL at the end of a line
  joins those two lines only. The words of the second that
  fit go up, the rest stays, and the lines below are left
  alone; the join used to merge the whole paragraph (BS on
  a line under an empty one also took the next line).
- Ctrl+B / Ctrl+I write the delimiters of the markup mode
  (MD or LIT). With MARKUP=OFF they do nothing.
- A selection larger than the clipboard (2 KB, 1 KB on
  S2ED): Ctrl+C copies its first part and shows
  [CLIPBOARD FULL], and Ctrl+X leaves it in the document.

Fixed
- Multi-line delete (DEL) on a full mapper segment no longer
  deletes subsequent lines if the joined start line fails.
- Mapper line ceiling calculation on 4 MB mappers no longer
  wraps at 16 bits.
- With the memory full, typing, pasting, Ctrl+D and
  Replace no longer move the cursor or mark the document
  modified when the line could not be stored.
- Backward search (Shift+F3 / Ctrl+R) now wraps correctly
  when a single match exists in the document.
- Markup styling (Ctrl+B / Ctrl+I) marks document modified
  when delimiters are applied to a selection.
- Command line parameter parsing clamps buffer bounds to
  prevent memory overflows; a switch longer than 40
  characters no longer loses the file name after it.
- Vi: v$ then d on the last line of the document cut the
  line short (one character kept of "CH" in CHARLIE).
- Ctrl+X on a selection larger than the clipboard deleted
  all of it but kept only the first part: the rest was lost.
- Ctrl+Z after a BS / DEL join in TXT mode did nothing (the
  join cleared the history), and Ctrl+Z after Ctrl+D joined
  the copy onto the original line.
- LEFT at column 0 of the top row, with UP keys pending,
  could leave the cursor past the end of the line.
- Shift+LEFT / Shift+RIGHT over a line end that scrolls
  could leave inverted cells on a line exactly as long as
  the margin.
- A line longer than the screen kept the bold or colour of
  its markup after MARKUP was set to OFF.

Other
- The unused MSX-DOS 1 file layer is gone (the editors
  already required MSX-DOS 2 or Nextor).


 -------- v0.7 (2026-10-15)

New
- The cursor rolls over the line ends in DEV mode too: RIGHT
  at the end of a line goes to the start of the next one,
  LEFT at column 0 to the end of the previous one. Never
  past the last line. Vi does it only in insert mode.
- F3 / Shift+F3 find the next / previous match in every
  profile (with no search yet, F3 opens Find & Replace).
- The file browser Name field edits like a line: LEFT /
  RIGHT move the cursor, HOME / Shift+HOME go to the ends,
  BS and DEL delete before / under it, and typing inserts
  at it. The Go to Line field edits the same way.

Changed
- Only F1 (with SELECT and F10) opens the menus: F2..F5 no
  longer do, which frees them for other commands. Inside a
  menu F1 goes back to File.
- Shift+BS deletes like BS (it did nothing).
- File browser: the selected entry keeps the accent colour
  only while the grid has the focus; with the focus on the
  Name field or a button it is shown blue on white, so it
  no longer looks as if the arrow keys would move it.
- The Name field keeps the case you type: it showed names
  in lower case but turned what you typed to upper case.
- Quitting with unsaved changes asks once: "Exit to
  MSX-DOS?" with YES (exit without saving) and SAVE (save,
  then exit; the default). ESC stays. The second "Save
  changes?" question is gone.
- The Emacs profile (EMC) is gone: STD, TED and Vi remain.
  A CFG with PROFILE=EMC now starts in STD.
- Unused code removed (the old profile cycling among it):
  about 150 bytes freed in every editor, which is what
  makes room for the above on S2ED.
- S2ED memory headroom: clipboard reduced to 1 KB (CLIPMAX
  1024), freeing 1024 bytes of TPA RAM in Page 1 (TPAFREE
  reaches 1024 B). Dialog and window engine refactored
  with shared address helpers (WINPOS4, WINOPN4, COLADDR,
  PATADDR), saving 188 bytes in S2ED.DAT (FTRFREE 445 B).

Fixed
- The manuals named v0.5 in their header since v0.6; they
  now carry the release they ship with, and the build checks
  it against the code and this history.


 -------- v0.6 (2026-10-15)

New
- Ctrl+D duplicates the current line immediately below in the
  STD and TED profiles, leaving the cursor on the new line.
- Vi profile: yy or Y yanks the whole current line to
  clipboard (with CRLF), so lines duplicate with p.
- Vi profile: visual selection supports u (lowercase),
  U (uppercase), and ~ (toggle case).
- Vi profile: ~ in normal mode toggles the case of the
  character under the cursor and advances one column.
- Dynamic VDP I/O port detection across all three targets via
  BIOS #0006/#0007, and 19T VRAM font bus upload pacing.
- S2ED: clean boot without text mode residual artifacts
  (ERAFNK before INITVDP) and sprite suppression (#D0).
- Edit > Rewrap (R) refills the selection, or the paragraph
  around the cursor, to the margin (TXT mode). It replaces
  Deselect: ESC already drops a selection.
- Switching WRAP from DEV to TXT in Settings asks "Rewrap
  document?" (default No) and rewraps every paragraph.

Changed
- Backspace / DEL reflow in TXT mode uses the rewrap engine:
  the joined line's indent is dropped, and a line already
  past the margin is split.
- Removed legacy Ctrl+K shortcut; profile cycling is managed
  exclusively via the Settings dialog.
- Removed Ctrl+W (wrap mode) and Ctrl+T (markup mode): both
  are chosen in Help > Settings, like every other setting.

Fixed
- Undo works on lines longer than the screen. An edit on a
  line past 80 columns (61 on S2ED / S61ED) could not be
  recorded: Ctrl+Z did nothing, or undid the wrong change
  and left the document marked as saved.
- A line join that runs out of memory no longer deletes the
  joined line.


 -------- v0.5 (2026-10-14)

New
- HOME and Shift+HOME jump directly to the top and bottom of
  the document in the STD profile.
- Quitting with unsaved changes asks whether to save before
  exiting. If confirmed, a named file is written directly;
  an untitled document opens Save As to enter a name.
  Cancelling Save As or an I/O error returns safely to the
  editor. If the user chooses not to save, a second prompt
  confirms discarding changes before leaving.

Changed
- Autoalign now reliably inherits the indentation (leading
  whitespace) of the previous line on Enter, instead of the
  legacy assembly heuristic that jumped to the second word
  on lines starting at column 0.
- Navigation in STD profile: Ctrl+Up / Ctrl+Down now pages
  up and down, and GRAPH+Up / GRAPH+Down jumps to the top
  and bottom of the document (along with their Shift
  selection equivalents), matching the ergonomic default
  of the TED profile.
- S6ED / S61ED: dialog buttons match the visual language of
  menus and settings: an unfocused button rests on the
  window background with plain text in the text colour, and
  the focused button is highlighted with a blue body (CLR_UI)
  and bold yellow text (COL_HI).
- S6ED / S61ED: Help > About opens with the lone OK button
  focused by default.


 -------- v0.4 (2026-10-13)

Changed
- S6ED / S61ED: buttons lose their brackets and the label is
  centred in the button. A 9-letter "[  YES  ]" ran past the
  button onto its border.
- S6ED / S61ED: a button without the focus is drawn in the
  text colour, so only the focused one looks highlighted.
- S6ED / S61ED: the status bar is as tall as the menu bar
  (8 px instead of 12).

Fixed
- Undoing back to the text last loaded or saved now clears
  the modified mark (*), and redoing away from it sets it
  again. Before, the mark stayed on after any edit.


 -------- v0.3 (2026-10-13)

Fixed
- Save As froze the machine after opening a file with the
  browser, File > New and typing something (all editors).
- File browser, changing drive (Nextor SD with two
  partitions):
  - only directories were listed, not files;
  - when DOS could not report the other drive's current
    directory, the browser kept the old path;
  - a directory with many files pushed the drives off the
    end of the list.
- Ctrl+A in a document longer than the screen put the cursor
  on the status bar, and every page move after it went wrong.
- S2ED, GREEN theme: menus, status bar and dialogs could not
  be read. They are now black on green.
- S6ED / S61ED: the focused button was white on yellow in the
  DARK theme. It is now the inverse of an unfocused button.
- S2ED: drop-down menus repeated the menu name as a first
  item you could not reach.

New
- The cursor shows the editing mode: underline while
  inserting, block in overwrite mode. In Vi: block in normal
  and visual mode, thin bar in insert mode, underline in
  replace mode (R).
- The file browser remembers the directory you left on each
  drive (A: -> B: -> A: returns to it).

Improved
- Extending a selection past the edge of the screen no longer
  repaints the whole selection on every row.
- File browser keystrokes repaint less: 30 to 60 per cent
  faster on a plain move.
- Cursor blink: 0.3 s instead of 0.4 s at 50 Hz.


 -------- v0.2 (2026-10-13)

Fixed
- The manual in the v0.1 bundle was UTF-8, so accented
  letters showed as two characters on the MSX. The bundle now
  carries SXED.TXT in the MSX character set and MANUAL.md in
  UTF-8. The disk images were already correct.
- Overwrite mode: [OVR] was shown but typing still inserted.
- S2ED: garbage in the Settings "Shadow" field, and
  SHADOW=OFF written on every save.

New
- Vi: r<c> replaces one character, R enters replace mode
  ([REP]) until ESC.

Other
- Tested on Japanese MSX2+ machines (a Boosted MSX2+ JP and a
  Sony HB-F1XV with 512 KB of mapper).


 -------- v0.1 (2026-10-07)

First release, for MSX-DOS 2 or Nextor.

- S6ED: MSX2 Screen 6, 80x24, 6x8 font in four weights.
- S61ED: MSX2 Screen 6, 61x24, 8x8 font in four weights;
  CGA, CPC and BIOS fonts included.
- S2ED: MSX1 Screen 2 (TMS9918), 61x22, two 4x8 glyphs per
  cell, colour themes. Runs under Nextor.
- Drop-down menus (F1-F5), windows with drop shadows.
- Dialogs: Go to Line, Find & Replace, Settings.
- File browser (Open / Save As) with drive changes.
- Key profiles STD, TED (TED 2.6) and EMC (Emacs), plus a
  modal Vi (normal, insert, visual, : commands).
- Undo / redo in a ring buffer.
- Word wrap, paragraph reflow, horizontal scrolling.
- Manual as MSX text (SXED.TXT) and Markdown (MANUAL.md).
